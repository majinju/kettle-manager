## 简介

数据世界部署手册，支持采用docker部署或手动部署

## 软件包

1. 相关文件
   1. sjsj.zip：部署包，可以采用docker方式部署，也可以手动部署
   2. 增量文件：因压缩包太大，很多时候只需要替换几个小文件，所以小修改都采用增量文件方式进行更新，将增量文件替换到解压后的包中即可
2. 将部署包sjsj.zip拷贝到服务器上，找一个磁盘空间大点的目录进行解压，推荐"/benma666"作为系统根目录（可以减少配置修改，非docker部署时配置中所有/benma666需要修改为该目录），进入解压后的目录

## docker部署

### 基础条件

1. linux系统：centos7，若你的版本部署有问题请切换
2. docker：20.10.17，若你的版本部署用问题请切换，内网部署安装流程
   1. 下载docker二进制文件：https://download.docker.com/linux/static/stable/x86_64/docker-20.10.17.tgz
   2. 下载完成后解压docker-20.10.17.tgz：`tar -zxvf docker-20.10.17.tgz`
   4. 将docker文件移到可执行文件目录下：`mv docker/* /usr/bin`
   5. 配置docker.service，vim /usr/lib/systemd/system/docker.service
      ```
      [Unit]
      Description=Docker Application Container Engine
      Documentation=https://docs.docker.com
      After=network-online.target firewalld.service
      Wants=network-online.target
      [Service]
      Type=notify
      ExecStart=/usr/bin/dockerd
      ExecReload=/bin/kill -s HUP $MAINPID
      LimitNOFILE=infinity
      LimitNPROC=infinity
      TimeoutStartSec=0
      Delegate=yes
      KillMode=process
      Restart=on-failure
      StartLimitBurst=3
      StartLimitInterval=60s
      [Install]
      WantedBy=multi-user.target
      ```
   6. 启动docker服务
      ```
      systemctl daemon-reload
      systemctl start docker.service
      docker info
      # 有人说我想开机自启动docker怎么办 一条指令解决
      systemctl enable docker
      ```
3. docker-compose：经测试如下版本正常，若你的版本部署有问题请切换
   1. `curl -L "https://github.com/docker/compose/releases/download/1.26.2/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose`
   2. 若下载有问题可以从网盘获取“docker相关/docker-compose”，放到“/usr/local/bin/docker-compose”
4. 依赖镜像：mysql、nginx、redis、openjdk:8-jre
   1. docker官方目前无法访问，网上搜索的很多镜像地址都不可用，阿里云的镜像可以正常使用。
   2. 也可采用网盘“docker相关”中我导出好的相关镜像，导入命令如：`docker load -i docker-nginx.tar `
5. 容器中的mysql数据库信息，kettle资源库：kettle_default，业务库：sjsj2_zs
```
    url: jdbc:mysql://benma666-mysql:3306/sjsj2_zs?useOldAliasMetadataBehavior=true&characterEncoding=utf-8&allowMultiQueries=true&serverTimezone=Asia/Shanghai
    username: root
    password: password
``` 
    
### 部署流程

1. 拷贝文件准备部署：`./deploy.sh copy`
2. 构建镜像：`./deploy.sh build`，非必须操作，后续步骤会自动构建，一般需要重构时使用
3. 防火墙端口设置：`./deploy.sh port`，可选，系统使用8090、8091两个端口，可以自行设置。
4. 基础组件部署：`./deploy.sh base`，该步骤会部署mysql、redis，mysql会执行初始化脚本，请等待mysql启动完成后进行后续操作。
5. 应用部署：`./deploy.sh app`，该步骤会部署后端和前端应用。
 
## 手动部署

### 基础条件

1. 支持操作系统：windows、linux
2. java环境：jdk8（数据世界jdk17没问题，但数据大师只能用jdk8）
3. 数据库：mysql8（目前主要支持mysql，系统本身支持oracle，但没有整理oracle数据库脚本，系统设计上支持多种数据库，将来适当优化即可支持更多数据库类型）。
4. redis，可选组件，若不需要可以关闭`spring.redis.enabled=false`
5. 数据库管理软件：Navicat数据库管理软件，用于数据库相关操作。

### 后端部署

#### 数据库创建

1. 同步库sjsj2_dev：用于更新时与开发环境同步，更新部署时会清空该库后导入开发环境数据。
1. 正式库sjsj2_zs：线上正式环境数据库，针对该用户下的数据库操作一定要仔细。

#### 数据导入

1. 执行数据库脚本时一定要谨慎，删错了很忧伤，建议尽量操作前进行备份。
2. 通过Navicat执行数据库初始化脚本“mysql/db/sjsj2_dev.sql”（初次部署在正式库sjsj2_zs执行，增量更新部署时在同步库sjsj2_dev执行），该脚本会删除表重建结构，<span style="color:red">请一定不要在正式环境执行</span>。

#### 配置文件

1. 各项配置基本都有说明，请根据需要修改，一般我们不需要修改主配置文件，参数太多。
2. 推荐修改的参数都已经放在了sjsj/hd/application-mysql、sjsj/hd/application-private这两个配置文件中，且每个配置项都有说明，请根据实际情况修改。

#### 启动系统

1. 双击sjsj/hd/start启动脚本进行系统启动。
2. 启动后根据线上实际情况修改：应用管理、数据载体、服务器、字典等数据。

### 前端部署

#### Nginx安装

1. Nginx下载地址：http://www.rpmfind.net/linux/rpm2html/search.php?query=nginx&submit=Search+...&system=&arch=
2. 查看nginx状态命令：systemctl status nginx，出现Unit nginx.service could not be found表示未安装nginx
3. nginx安装命令：rpm -ivh nginx-1.20.1-1.el7.ngx.x86_64.rpm
4. nginx启动：systemctl start nginx
5. 查看是否启动成功：Active: active (running) 为正在运行
6. 补充：重启命令：systemctl restart nginx，停止命令：systemctl stop nginx

#### Nginx配置

1. 修改nginx配置，采用“nginx/conf/nginx.conf”覆盖“/etc/nginx/nginx.conf”
2. 根据实际情况修改其中proxy_pass、root两个参数
3. nginx测试：nginx -t,出现test is successful说明测试成功
4. nginx配置重新加载：nginx -s reload

#### 前端包部署

1. 将前端包“nginx/qd”放到上述nginx配置文件中root对应的目录，并改名为sjsj。

## 系统升级

### 备份（重要）

1. 强烈建议先将线上库数据进行完整备份以备不测。

### 数据导入sjsj2_dev

1. 数据库相关资源在部署包的“mysql/db”目录中，执行数据库脚本时一定要谨慎，删错了很忧伤，建议尽量操作前进行备份。
1. 通过Navicat在创建的同步库sjsj2_dev中执行数据库初始化脚本“sjsj2_dev.sql”，该脚本会删除表重建结构，<span style="color:red">请一定不要在正式环境执行</span>。

### 数据更新sjsj_zs

1. 根据系统更新记录将数据库表结构变化更新到线上正式库中，当结构变化较大时，也可以采用Navicat的工具进行数据库结构比较，但千万要自己小心，特别是drop之类的操作要删除，表结构比对配置参考如下。
![表结构同步对比配置.png](https://trimdata.cn:2000/sjsj-zs-ht/default?sjdx.dxdm=SYS_QX_QTQX&sys.cllx=download&yobj.id=C355D9EA6C4E492A89FDA7F310038172)
1. 打开“upscript.sql”升级脚本，根据实际情况替换用户名等信息，为了避免数据错位，若发现字段顺序与开发环境不一致，建议sql语句直接补充完整的字段，再执行升级脚本。

### 应用更新

1. 备份当前正常运行的部署包，更换新的应用部署包测试功能是否正常。
